# Astona — Admission & Payment (Sub-project 2) Design

Source: SDD §3.1, §4.2, §5, §7, §11; TRD; RTM FR-002/003. Real bKash driver is **deferred** (owner will add the gateway later):
this sub-project ships a `PaymentGateway` interface + a Fake gateway (local/test only). Defaults: full payment (OQ-03),
hard-close when full (OQ-07), refund = status only (OQ-06), offline path disabled (OQ-13), no IPN reliance (OQ-05).
Out of scope: WP user provisioning/SMS/login (sub-project 3), admin review desk, waitlist, installments, Turnstile
(a `cc_verify_captcha` filter hook returns true; honeypot + rate limit are the MVP bot defence).

## Tables (already created in includes/class-migrations.php v2 — do not change)
cc_applications, cc_invoices, cc_payments, cc_payment_events, cc_idempotency (see migration for columns).
Table name helper: `$wpdb->prefix . 'cc_applications'` etc. Times are UTC `Y-m-d H:i:s`.

| support/class-rate-limiter.php | foundation | `CC_Rate_Limiter::allow(string $bucket, int $limit, int $window_seconds): bool` (transient/object-cache backed, atomic enough for MVP); `CC_Rate_Limiter::client_ip(): string` |

| payments/interface-payment-gateway.php | payments | `interface CC_Payment_Gateway { id(): string; create_payment(array $invoice, string $callback_url): array /* [gateway_payment_id, redirect_url] */; execute(string $gateway_payment_id): array /* [status: completed|failed|cancelled|pending, trx_id, amount(float), raw(array)] */; query(string $gateway_payment_id): array /* same shape */ }` |
| payments/class-fake-gateway.php | payments | dev/test gateway; stores state in an option/transient keyed by gateway_payment_id; redirect_url → `/wp-json/cc/v1/payments/fake/checkout?pid=…` (a minimal HTML page with Pay / Fail / Cancel buttons that set the fake state then redirect to callback). Refuses to run when `wp_get_environment_type()==='production'` |
| payments/class-gateway-factory.php | payments | `CC_Gateway_Factory::make(): CC_Payment_Gateway` — returns Fake now; reads `CC_PAYMENT_GATEWAY` env/const (`fake` default); unknown → WP_Error/exception. bKash driver plugs in here later |
| payments/class-settlement.php | payments | `CC_Settlement::settle(int $payment_id, string $source): array` returns `[ 'result' => 'settled'|'already_settled'|'not_completed'|'mismatch'|'batch_full', 'application_ref' => string ]`. In ONE DB transaction with `SELECT … FOR UPDATE` on payment, then batch rows: verify gateway status via `gateway->query()` (never trust caller), amount == invoice amount, invoice not void; then payment→completed(+trx_id, settled_at), invoice→paid, application→approved, `seats_taken+1` only if `seats_taken < capacity`; if batch full → payment stays completed, application→`waitlisted`? NO: application→`pending` + payment `reconcile_needed` (needs human; refund is a status field) and result `batch_full`. Amount mismatch → payment `reconcile_needed`, result `mismatch`. Idempotent: second call returns `already_settled`. Appends a row to cc_payment_events (event_key unique) for dedupe. After commit: `do_action('cc_application_settled', $application_id, $payment_id)` exactly once |
| payments/class-reconciler.php | payments | `CC_Reconciler::init()`; every minute (Action Scheduler recurring action if `as_schedule_recurring_action` exists, else WP-Cron event `cc_reconcile`): payments in `initiated`/`executing` older than 3 min → `execute/query` via gateway → `settle(...,'poll')`; stale >30 min and never paid → `cancelled`. Method `CC_Reconciler::run(): int` returns count processed (testable) |
| payments/class-rest-payments.php | payments | `CC_Rest_Payments::init()` registers `GET /cc/v1/payments/callback` (gateway-agnostic; params untrusted: `pid` only; looks up payment, runs execute()+settle(), then 302 to the confirmation page `/admissions/?ref=<public_ref>&paid=1`), and the Fake checkout route. No-store headers |
| admissions/class-application-repository.php | admissions | `create(array $data, string $idempotency_key): array|WP_Error` (transaction: insert application + invoice number `INV-YYYYMMDD-<id>`; replay with same key returns the original row); `find_by_ref(string $ref): ?array`; `status_view(string $ref): array` (minimal public fields) ; `ulid(): string` |
| admissions/class-photo-store.php | admissions | `store(array $file, string $ref): string|WP_Error` — JPEG/PNG ≤2 MB, finfo MIME sniff, re-encode via GD/Imagick (strips EXIF), save under a private dir outside web root (`CC_PRIVATE_DIR` const, default `WP_CONTENT_DIR/../private` → `/var/www/private` in docker), random filename |
| admissions/class-rest-admissions.php | admissions | `GET /cc/v1/forms/admission-token` (returns idempotency key UUID + honeypot field name; no-store); `POST /cc/v1/applications` (multipart; `Idempotency-Key` header required; honeypot; rate limit 5/IP/10 min; validates every field; batch must be open per CC_Status_Chip & `application_open`; calls repository then gateway `create_payment`; returns `{ref, redirect_url}` 201; replay → 200 same body); `POST /cc/v1/applications/{ref}/payment` (retry payment for same invoice if unpaid; 5/ref/hour); `GET /cc/v1/applications/{ref}/status` (30/min; minimal fields: status, payment_status) |

Errors: `{code, message, details?}`; 400/404/409/422/429. All routes have `permission_callback` (public routes: `__return_true` with explicit comment) and arg schemas.
Application fields (PRD-FUNC-002): batch_id, full_name, gender(m/f/o), dob, id_doc_type, id_doc_number, photo (file), student_phone, guardian_name, guardian_phone, email(optional), institution, class_level, passing_year(optional), roll_no(optional), branch_pref(optional), consent (required checkbox). Under-13 etc. not enforced. Student phone must be unique per ACTIVE approved application for the same batch (409).

## Theme (admissions agent)
`page-admissions.php` shows the real form when `?batch=` is a valid OPEN batch (keep existing validation/closed/not-found notices), a confirmation view when `?ref=…`, polling `GET …/status` every 3 s up to 60 s ("payment pending" state), success / failed (with Retry Payment) states. `assets/js/admission.js` (vanilla, no jQuery): fetch token, inline validation, auto-format phone, photo preview, disables submit on first click, `aria-live` errors, labels + fieldset/legend. Styles appended to `assets/css/main.css` under `/* Admission */`. Enqueue admission.js only on the admissions page (functions.php).

## Testing
tests/unit: phone, crypto, idempotency/event_key, fake gateway state. tests/integration (run inside the wpcli container via `wp eval-file`): settle() happy path, double settle once, amount mismatch, batch full, replayed idempotency key, reconciler picks up abandoned payment. tests/e2e/admission.sh: curl full flow with Fake gateway.
