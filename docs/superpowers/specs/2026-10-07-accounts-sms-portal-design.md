# Astona — Accounts, SMS & Student Portal (Sub-project 3) Design

Source: SDD §2, §3.1 steps 5/8, §4.2, §5.1–5.2, §6, §7, §11; RTM FR-004/005/006/010/019/020. Defaults (RTM): credentials by SMS =
temp password (72 h, forced change) + OTP login (OQ-11); phone is the login; SMS gateway not chosen (OQ-02) → driver interface +
Fake driver now, real BulkSMSBD/GreenWeb drivers later; one student per phone (A-09). Out of scope: live-class gate, targeted
notices (SP4), course viewer/lessons, admin roster/review desk, phone change (displayed read-only: "contact us"), password
recovery by SMS beyond OTP login, parent accounts.

## Tables (created in includes/class-migrations.php v3 — do not change)
cc_students, cc_enrollments, cc_otp, cc_sms_log (see migration). Times UTC `Y-m-d H:i:s`.

## Ownership (wp-content/plugins/coaching-platform/includes/…, all loaded by coaching-platform.php; classes with `init()` are auto-called)

| sms/class-sms-fake-driver.php | SMS | stores messages in non-autoloaded option `cc_fake_sms_outbox` (last 50: to, body, time) — usable only when env is local/development AND CC_SMS_PRIMARY (or fallback) is 'fake'; helper `CC_Sms_Fake_Driver::outbox(): array`, `clear()` |
| sms/class-sms-factory.php | SMS | `CC_Sms_Factory::primary()` / `fallback(): ?CC_Sms_Driver` from const/env `CC_SMS_PRIMARY`, `CC_SMS_FALLBACK` (names: fake; real drivers plug in later); unset → throws RuntimeException (sending marks the log row failed with a clear error; never crashes a request) |
| sms/class-sms.php | SMS | `CC_Sms::init()` registers the Action Scheduler (fallback WP-Cron single event) handler `cc_send_sms`; `CC_Sms::queue(string $to_e164, string $template, array $vars = [], string $related_type = '', int $related_id = 0): int` renders a template (`credentials`, `otp`, `receipt` — English; Bangla variants allowed, bodies must stay GSM-safe or Unicode-aware), writes cc_sms_log (to_phone masked via CC_Phone::mask in logs only; full number stored because it's needed to send; body stored ENCRYPTED via CC_Crypto in body_enc ONLY for template `credentials`/`otp` NEVER — store body_hash only for those; others may store body_enc), schedules the async send, returns log id; sending: retry 3× with backoff on primary, then fallback driver, then status failed + error_log (no secrets); `CC_Sms::segments(string $body): int` (GSM-7 160/153, UCS-2 70/67). `CC_Sms::render(string $template, array $vars): string` public + testable. | enrollment/class-roles.php | ENROLL | `CC_Roles::init()` registers role `cc_student` (no caps except `read`), hides admin bar for students; on `admin_init`/`wp_login` blocks wp-admin and wp-login access for cc_student (redirect `/student/`) except admin-ajax/REST |
| enrollment/class-enrollment-repository.php | ENROLL | `create(int $user_id, int $batch_id, int $application_id): int` (idempotent by application_id), `for_user(int $user_id): array` (joined with batch/course title, schedule_text, delivery_mode, status), `user_has_active(int $user_id, int $batch_id): bool`, `student_row(int $user_id): ?array`, `mark_pw_changed(int $user_id)` |
| enrollment/class-provisioner.php | ENROLL | `CC_Provisioner::init()` hooks `cc_application_settled` ($application_id, $payment_id) → schedules async action `cc_provision_student` (Action Scheduler, WP-Cron fallback) → `CC_Provisioner::provision(int $application_id): array` returns `[user_id, created(bool), enrollment_id]`; idempotent; in one logical unit: find user by login = normalized phone digits (`+8801…` → `8801…`; user_login `8801XXXXXXXXX`) else `wp_insert_user` role cc_student (random unusable email `<digits>@students.invalid` if no email), cc_students row (must_change_pw=1, temp_pw_expires=+72h) and set a random 10-char temp password (A-Za-z2-9, no ambiguous chars) ONLY for new users; existing student → add enrollment only, no password change, SMS says 'new course added'; set cc_applications.user_id; create enrollment (status active, expires_at NULL); queue SMS (`credentials` with phone+temp password+login URL, or `enrolled` for existing). Failure at any step is retried by the scheduler and never creates duplicates or a second SMS (guard with application-level flag/enrollment existence) |
| auth/class-otp.php | AUTH | `CC_Otp::request(string $phone_e164, string $purpose = 'login'): bool`, `CC_Otp::verify(string $phone, string $code, string $purpose = 'login'): bool`; 6 digits via random_int; stored as hmac-sha256(wp_salt('auth'), phone.code); expires 5 min; max 5 wrong attempts then 15-min lock; single use; cleanup of expired rows via the scheduler |
| auth/class-rest-auth.php | AUTH | routes under `/cc/v1`: `POST /auth/login {phone,password}`, `POST /auth/otp/request {phone}` (always the same 200 response whether or not the phone exists; limits 3/phone/h, 10/IP/h), `POST /auth/otp/verify {phone,code}`, `POST /auth/logout` (cookie + REST nonce), `POST /me/password {current_password,new_password}` (min 10 chars; clears must_change_pw/temp_pw_expires; destroys other sessions). Login: uniform error 'Invalid phone or password' for unknown phone / bad password / expired temp password / non-student user; refuses non-`cc_student` users; limit 10/IP/15 min plus per-phone bucket; on success `wp_set_auth_cookie` (2 days; 14 with remember), response `{redirect}` = `/student/` or `/student/profile/?change=1` when must_change_pw; all responses `Cache-Control: private, no-store` |
| auth/class-student-guard.php | AUTH | `CC_Student_Guard::require_student(): WP_User` helper for portal pages (redirects to `/student/login/?redirect=…` when not logged in/not a student, forces `/student/profile/?change=1` when must_change_pw), `CC_Student_Guard::send_no_store()` |
| portal/class-portal-router.php | PORTAL | `CC_Portal_Router::init()`: rewrite rules for `/student/` (dashboard), `/student/login/`, `/student/payments/`, `/student/payments/receipt/`, `/student/profile/`; query var `cc_portal`; `template_include` maps to theme files `student-login.php`, `student-dashboard.php`, `student-payments.php`, `student-receipt.php`, `student-profile.php`; flushes rewrite rules once when plugin version/db option changes; sends no-store headers on all of them; `X-Robots-Tag: noindex` |
| portal/class-portal-data.php | PORTAL | pure data helpers for templates: `dashboard(int $user_id): array` (enrollments + placeholder sections), `payments(int $user_id): array` (join applications→invoices→payments for the user's own applications only), `receipt(int $user_id, int $payment_id): ?array` (owner-only; null otherwise) |
| Theme (templates `student-login.php` [AUTH], `student-dashboard.php`, `student-payments.php`, `student-receipt.php`, `student-profile.php`, `template-parts/student-nav.php` [PORTAL]) | AUTH/PORTAL | dashboard: enrolled courses/batches cards (course, batch, mode, schedule, status chip), a 'Today's schedule' card and a 'Notices' card saying coming soon (SP4), quick links; payments: table of date/amount/status/trx id + receipt link; receipt: printable HTML (invoice number, student, course/batch, amount, trx id, paid time) — 403-style notice for non-owner; profile: read-only name/phone, editable guardian name/phone + email (server-validated via REST `PATCH /me/profile`, owned by PORTAL in class-portal-data.php or a new includes/portal/class-rest-portal.php registered through CC_Portal_Router::init), password change form (current + new) hitting `/me/password`; login page: phone + password, 'Login with OTP' toggle (request code → enter code), uniform errors, rate-limit message, `aria-live`, labels, no jQuery, `assets/js/student-login.js`, `assets/js/student-portal.js`, CSS appended under `/* Student portal */`; enqueue those scripts only on portal pages (functions.php edit by PORTAL; AUTH adds only its script line via the same function — coordinate by re-reading before editing) |

Admission integration: after payment the confirmation page text in admission.js/page-admissions.php should say an SMS with login details is on its way and link to `/student/login/` (PORTAL owner).

Errors `{code,message,details?}`; all routes have permission_callback and arg schemas; sensitive responses no-store; never log OTPs/passwords/SMS bodies for credentials/otp.
