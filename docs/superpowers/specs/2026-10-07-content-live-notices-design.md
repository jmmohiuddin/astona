# Astona — Course Content, Live Classes & Targeted Notices (Sub-project 5) Design

Source: PRD-FUNC-004, 005, 006, 009 (reject notification), 010 (modules/lessons), 015 (PDF notes, pulled forward because lessons carry them);
SDD §3.2–3.3, §5.2, §7; WF-015/016/017/018/024/027/030. Closes the remaining P0 gaps. Out of scope: React nested editor (server-rendered
forms instead), instructor batch-scoped UIs (roles stay owner/staff), attendance, quiz, media-library rules (SP6), blog/gallery/contact (SP6).

## Tables (created in includes/class-migrations.php v5 — do not change)
cc_modules(batch_id,title,sort_order), cc_lessons(module_id,title,scheduled_at,sort_order,attachment_path,attachment_name),
cc_live_classes(batch_id,lesson_id,title,starts_at,ends_at,provider,meeting_url_enc,created_by,updated_at), cc_join_log, cc_notice_targets(notice_id,batch_id).
Times UTC. New caps (CORE-owned file, edited by CONTENT agent only): `cc_manage_content`, `cc_manage_live`, `cc_manage_notices` — owner + staff + administrator get all three;
instructor none; student none. New admin submenus (CONTENT agent edits class-admin-menu.php + class-admin-roles.php + their tests once for all three):
`cc-content` (Course content), `cc-live` (Live classes), `cc-notices` (Notices) → renderers `CC_Admin_Content::render`, `CC_Admin_Live::render`, `CC_Admin_Notices::render`.

| notices/class-notice-access.php | NOTICES | `CC_Notice_Access::init()`: batch-targeted notices must be INVISIBLE publicly: exclude them from the public `cc_notice` archive/main queries (pre_get_posts / posts_where with NOT EXISTS on cc_notice_targets), from REST `/wp/v2/cc_notice` for non-admins (rest_cc_notice_query + single GET), from search/feeds/sitemaps (wp_sitemaps_post_types_entries/ query filter), and the single permalink returns 404 unless the viewer is an enrolled active student of a target batch or has cc_manage_notices; archived notices 404 publicly |
| admin/class-admin-notices.php | NOTICES | admin screen 'Notices' (WF-024): list (title, audience, status, critical, date) with status tabs (Draft/Scheduled/Published/Archived), form (title, rich text via wp_editor + wp_kses_post, audience: Public or one/more batches, critical SMS checkbox, schedule date-time), mandatory AUDIENCE PREVIEW step before publish ('Will be visible to N students in Batch A, B; SMS to N phones' — computed via recipients()), publish confirmation result ('Sent to N students'), archive/unarchive; cap `cc_manage_notices`+nonce, audited. Please contact us.') in includes/sms/class-sms.php and call it from CC_Admin_Applications::reject() after a successful reject (queue failure must not fail the reject; audited note stays 'rejected') |
| portal/class-portal-courses.php | PORTAL2 | `CC_Portal_Courses::init()`; student routes registered through the existing CC_Portal_Router (PORTAL2 owns the router edits for ALL new routes): `/student/courses/` (my batches), `/student/courses/{batch_id}/` (modules/lessons, PDF links, live-class rows with Join state), `/student/notices/` (batch-targeted + public feed, filter by batch when >1, paging 20), `/student/resources/{lesson_id}/` (gated PDF stream: logged-in cc_student with ACTIVE enrollment in the lesson's batch, finfo MIME application/pdf, Content-Disposition attachment with the stored name sanitised, no-store, nosniff, path containment, 404 otherwise — same response for 'no such lesson' and 'not enrolled'); theme templates student-courses.php, student-course.php, student-notices.php, assets/js/student-live.js (Join button: states inactive/active/launching/denied/ended per WF-017 with aria-label stating the state and countdown from SERVER time offset, POST /cc/v1/live-classes/{id}/join then window.open(url,'_blank','noopener') — the URL only ever lives in a JS local variable) ; dashboard (student-dashboard.php + CC_Portal_Data::dashboard): replace the 'Today's schedule' placeholder with real live classes/lessons for the next 7 days (today first; 'next class' fallback) and the 'Notices' placeholder with the top 3 `visible_to_user` notices; deactivated/expired enrollments never contribute content; nav gets 'My courses' and 'Notices' |

All admin handlers: capability + nonce on every handler, esc_* output, $wpdb->prepare, no PII in URLs, audit via CC_Audit::log (no meeting URLs, no file contents).
Student-facing responses: no-store. Meeting URL: encrypted at rest (CC_Crypto), never in HTML, never in logs/audit, only in the join response body.
